# PDF / print edition

Builds `pdf-build/Mastering-XRR-Fitting.pdf` (the name follows `BOOK_TITLE` in
`src/lib/site.mjs`) by rendering the live site through Chromium. It is ported from the
pipeline of the author's earlier book, *Vacuum Engineering* (the "Vacuum book"). That book's
quiz, YouTube, two-volume and problem-set logic was removed.

## Regenerate

From the repo root:

```sh
npm run build                 # whenever content changed; assemble.py reads dist/ too
npm run preview               # serves http://localhost:4331/MasteringXRR/ (leave running)

npm run pdf:render            # -> pdf-build/out/*.pdf + manifest.json
npm run pdf:assemble          # -> pdf-build/Mastering-XRR-Fitting.pdf
npm run pdf:verify            # the gate; exits non-zero on any failure
```

On a Windows console, set `PYTHONIOENCODING=utf-8` for the two Python steps.

To render a subset, or the component sampler, run the renderer directly:
`node pdf-build/render-sections.mjs "" "" introduction,sampler`. The sampler (`/sampler/`)
is not part of the book. It exercises every component, so render it after changing styles or
the pipeline. A subset whose links point at unrendered pages cannot be assembled, and
`assemble.py` says so.

Python needs PyMuPDF (`fitz`), pypdf, beautifulsoup4 with lxml, and pytest.
Tests: `npm run test:py` (pytest) and `npm run test` (Vitest, which includes `print-box.test.mjs`).

## The stages and their gates

1. **`render-sections.mjs`** reads the page list from `/sections.json`, so reading order
   cannot drift from the content collection. For each page it:
   - hides the web chrome;
   - **removes every `:::web-only` block and shows every `:::print-only` block, then asserts
     both**;
   - rewrites same-page `#fragment` links into URLs (see below);
   - opens every `<details>`;
   - freezes plot widgets and drops control-only widgets;
   - prints A5.

   Two gates run on every page. The **print-box gate** (`print-box.mjs`) fails any page wider
   than 515 px. Chrome would otherwise shrink that whole section and reprint every label
   smaller. The **print/web gate** fails the run if any web-only content survives or any
   print-only block is hidden. The manifest is deleted first and written only when every page
   passed. Old section PDFs are removed, so `out/` holds only this run.
2. **`assemble.py`** does the following:
   - merges the body;
   - finds every Contents heading in it, meaning every h2 except `Sources`;
   - renders the cover, a title page and a Contents grouped by Part, with real page numbers. The
     title page (author, affiliation, ORCID, edition, DOI, licence, how to cite) takes the edition,
     DOI, year and web address from `CITATION.cff`, so bump that file before a release. The cover's hero
     art is `cover-hero.svg`, generated by `python pdf-build/cover_hero.py` from the Ch 18 fit
     data, and runs `cover-math.mjs`, which typesets the two ghost formulas into `cover-math.html`
     (rerun it only if that data, the formulas or the hero design changes);
   - stamps running heads (left "Chapter 4: …", right the current h2, truncated on a word
     boundary);
   - stamps "n / N" page numbers;
   - links every Contents row;
   - rewrites every localhost cross-reference into a page jump (`links.py`);
   - writes the outline.

   It fails when:
   - a Contents heading cannot be found;
   - a row cannot be linked;
   - a link points at a page not in the build;
   - **any cross-reference in the web text has no jump in the PDF.**
3. **`verify_pdf.py`** checks the PDF itself:
   - A5 pages;
   - a title page that names the author, affiliation, ORCID, edition, DOI and licence;
   - an outline that matches the manifest;
   - Contents margins, running head and links;
   - running heads and page numbers;
   - the type-size floors (7.9 pt text, 5.9 pt scripts);
   - no e-notation, **no em-dash** (STYLE.md §4.2), and no leftover Markdown;
   - every figure caption present and whole;
   - the 124 mm text column;
   - no dead preview links, and every link target in range.

   **Expected counts are derived from `out/manifest.json` and `dist/`**, never typed in,
   because the book changes while it is drafted. A check that needs prose to measure reports
   SKIP until there is enough of it.

## Things this pipeline found that the Vacuum one did not

- **Same-page links were silently lost.** Chrome prints `href="#fig-4-1"` as a
  named-destination link, and pypdf's page merge drops named destinations. So every
  "see Figure 4-1" inside its own chapter vanished, and every check stayed green. The renderer
  now rewrites these links to `…/page/?xref#fig-4-1`. The `?xref` is required, because
  Chrome still treats an absolute URL to the *same* document as a named destination. The
  assembler compares against `links.expected_internal_targets()`, so a future loss fails the
  build.
- **Short headings could not be located.** The heading finder skipped any probe under 6
  characters, so a heading like "Icons" was unfindable. Now a short heading is accepted when it
  occurs on exactly one page of its section. When it is ambiguous, the build still fails.
- **Figure cross-references** now resolve to the figure's page (by its "Figure N-M:" label)
  instead of the chapter's first page.

## Where the long reasons are

The print CSS and the gates carry one-line reasons. The full reasoning, with the measurements
behind each rule, is in the Vacuum book's `pdf-build/render-sections.mjs`, `print-box.mjs`,
`assemble.py`, `links.py` and `verify_pdf.py`. Examples:
- why tables and callouts may break but figures may not;
- why KaTeX display math is allowed to wrap;
- why the print box is 515 px;
- why the type floors are 7.9 pt and 5.9 pt.

Read those before changing a rule here.
